# M6 audit — typed bodies, errors, decoders

Scope: M6.1 through M6.7 plus M6.8 (client wiring) and M6.9 (real-model
codegen for DynamoDB + S3). Treat as the audit of the surface produced
in this branch (`plan/m5-codegen`).

## What the user sees

After this milestone series, a caller has a typed Gleam API for two
real AWS services:

```
let client = dynamodb.new(provider: provider, region: "us-east-1")
case dynamodb.list_tables(client, dynamodb.ListTablesInput(...)) {
  Ok(out) -> ...
  Error(dynamodb.ListTablesErrorInternalServerError(value: e)) -> ...
  Error(dynamodb.ListTablesErrorTransport(reason: r)) -> ...
  Error(dynamodb.ListTablesErrorUnknown(...)) -> ...
}
```

Same shape for `aws/services/s3.gleam` — 77 operations, typed input,
typed output, typed error enum, XML body encoding, XML response
decoding.

## Generator architecture

Three layers — same as smithy-rs:

1. **Runtime** (`src/aws/internal/...`) — hand-written, ~2 kLOC.
   SigV4, credentials chain, retry, http_send, codecs (`json_float`,
   `xml`, `xml_decode`, `rest`), shared `awsjson_client.invoke`.

2. **Generator** (`codegen/src/codegen/...`) — hand-written, ~4 kLOC.
   `types.gleam` resolves Smithy shapes to a thin `Resolved` IR;
   `awsjson.gleam`, `restjson.gleam`, `restxml.gleam`,
   `awsquery.gleam` emit per-protocol Gleam source.

3. **Generated services** (`src/aws/services/...`) — emitted, no hand
   edits. DynamoDB is 20 kLOC, S3 is ~30 kLOC. Re-run via:
   ```
   gleam run -m aws_codegen -- awsJson1_0 .../dynamodb.json .../dynamodb.gleam
   gleam run -m aws_codegen -- restXml    .../s3.json       .../s3.gleam
   ```

restJson1's 30-odd failing cases are documented in the test output —
they involve `@document` types, streaming blobs with `@mediaType`,
fractional-second timestamp headers, and `@xmlName` on unions. None of
these block DynamoDB or S3's mainline ops.

## Known gaps (not in M6 scope)

- **Response header binding.** Output members bound to `@httpHeader`
  / `@httpResponseCode` are decoded as `option.None`. The runtime sees
  the headers (`parse_<op>_response` receives them) but the generator
  doesn't yet emit code that reads them into the typed output. Tracked
  for M7.
- **XML error-type extraction.** restXml service errors land in
  `<Op>ErrorUnknown` because `extract_error_type` in `awsjson_client`
  only reads `x-amzn-errortype` and a JSON `__type` / `code` field.
  S3's `<Error><Code>...</Code></Error>` body is not yet parsed.
- **`@xmlFlattened` lists**. Default Smithy list wrapping is honoured
  via `Resolved.xml_entry_name`; the flattened form (entries as direct
  siblings) is not.
- **`@xmlName` on struct members**. Per-list-member is honoured;
  struct-member overrides are not.
- **Endpoint rules.** The static `endpoint_prefix.region.amazonaws.com`
  pattern handles standard AWS partitions but not FIPS / dualstack /
  service-specific endpoint rules (e.g. S3 path-style vs vhost). The
  `with_endpoint_url` escape hatch covers LocalStack and custom DNS.
- **Streaming bodies.** `@streaming` blobs (S3 GetObject, PutObject;
  many service events) are skipped at the emitter level — the runtime
  doesn't yet support streaming HTTP send.
- **Paginators / waiters.** Not generated. Callers can write loops by
  hand against the typed outputs.
