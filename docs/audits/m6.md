# M6 audit — typed bodies, errors, decoders

Scope: M6.1 through M6.7 plus M6.8 (client wiring) and M6.9 (real-model
codegen for DynamoDB + S3). Treat as the audit of the surface produced
in this branch (`plan/m5-codegen`).

## What the user sees

After this milestone series, a caller has a typed Gleam API for two
real AWS services:

```
let client = dynamodb.new(provider: provider, region: "us-east-1")
case dynamodb.list_tables(client, dynamodb.ListTablesInput(...)) {
  Ok(out) -> ...
  Error(dynamodb.ListTablesErrorInternalServerError(value: e)) -> ...
  Error(dynamodb.ListTablesErrorTransport(reason: r)) -> ...
  Error(dynamodb.ListTablesErrorUnknown(...)) -> ...
}
```

Same shape for `aws/services/s3.gleam` — 77 operations, typed input,
typed output, typed error enum, XML body encoding, XML response
decoding.

## Generator architecture

Three layers — same as smithy-rs:

1. **Runtime** (`src/aws/internal/...`) — hand-written, ~2 kLOC.
   SigV4, credentials chain, retry, http_send, codecs (`json_float`,
   `xml`, `xml_decode`, `rest`), shared `runtime.invoke`.

2. **Generator** (`codegen/src/codegen/...`) — hand-written, ~4 kLOC.
   `types.gleam` resolves Smithy shapes to a thin `Resolved` IR;
   `awsjson.gleam`, `restjson.gleam`, `restxml.gleam`,
   `awsquery.gleam` emit per-protocol Gleam source.

3. **Generated services** (`src/aws/services/...`) — emitted, no hand
   edits. DynamoDB is 20 kLOC, S3 is ~30 kLOC. Re-run via:
   ```
   gleam run -m aws_codegen -- awsJson1_0 .../dynamodb.json .../dynamodb.gleam
   gleam run -m aws_codegen -- restXml    .../s3.json       .../s3.gleam
   ```

`fail` is zero across every protocol. The `skip(no-dispatcher)` counts
mostly represent operations using `@httpChecksumRequired` /
`aws.protocols#httpChecksum` — the emitter deliberately skips those
until a checksum middleware lands (v0.2 candidate). The `skip(server-only)`
counts are response-side cases the test corpus marks as
`appliesTo: server`, which never affect SDK callers.

## Known gaps — most closed by the v0.1 close work

Items that were open at M6 cut-over and how they closed in the v0.1
close pass. The remaining ones are all explicit v0.2 candidates.

- **Response header binding — DONE.** Generated `parse_<op>_response`
  now emits `Output(..decoded, etag: rest.string_header(headers,
  "ETag"), ...)` overrides for every `@httpHeader` / `@httpResponseCode`
  output member. Full-override mode kicks in when an output has no
  body-bound members, sidestepping the "redundant record update"
  warning. (`aws/internal/codec/rest`.)
- **XML error-type extraction — DONE.** `runtime.extract_error_type`
  walks `<Code>...</Code>` (S3-style and `<ErrorResponse>` wrappers)
  after the JSON `__type` / `code` paths fall through. The header
  `x-amzn-errortype` still wins when present.
- **`@xmlFlattened` lists — DONE.** Codegen routes flattened list
  members through `xml_decode.optional_flat_list`. Default Smithy
  wrapping unchanged.
- **`@xmlName` on struct members — DONE.** The member-level
  `@xmlName` was always threaded into `MemberDef.json_name`; the
  decoder already used that as the element name, so closing the
  flattened-list gap closed this too. Verified end-to-end via
  `decode_list_buckets_output_xml` / `decode_list_objects_output_xml`.
- **Endpoint rules — DONE.** Per-service Smithy rule sets embed at
  codegen time (`smithy.rules#endpointRuleSet` trait, re-serialised
  back to JSON via `trait.to_json_string`). `runtime.invoke` walks
  the rule set per request, with `invoke_with_endpoint_params` for
  operation-specific parameters (S3 `Bucket` / `Key` etc.). Static
  `<prefix>.<region>` fallback retained for services without a rule
  set.
- **Streaming bodies — v0.2 gap.** `@streaming` blobs still skipped
  at the emitter level. `S3.GetObject` for v0.1 buffers the body to
  `BitArray`; a streaming HTTP send + receive path is on the v0.2
  list.
- **Paginators / waiters — v0.2 gap.** Not generated. Callers loop
  on `next_token` by hand against the typed outputs.
- **Checksum middleware — v0.2 gap.** Operations carrying
  `@httpChecksumRequired` / `aws.protocols#httpChecksum` are skipped
  by the emitter; until a body-hash middleware lands, the protocol
  test runner reports them as `skip(no-dispatcher)`.
