# M5 drift audit — vs aws-sdk-rust

This document captures, at the close of M5, the parity gap between
what our Gleam codegen produces and what `aws-sdk-rust`'s codegen
produces for the same Smithy inputs. Format follows the saved feedback
memory (MCP-first design, MCP-verified completion): inventory parity,
behavioural parity, save findings.

## 1. Architectural parity

Both projects split the same way:

| Concern | aws-sdk-rust | this repo |
|---|---|---|
| Smithy parser | `smithy-rs` / Java `software.amazon.smithy.model` | `codegen/src/smithy/{shape,trait,shape_id,model}.gleam` |
| Protocol classification | Kotlin `ProtocolLoader` | `codegen/src/aws_codegen.gleam:find_service` + `pick_emitter` |
| Per-protocol emitter | `codegen-aws-sdk-bundled/.../JsonHttpBindingProtocol.kt`, `restJson1`, `restXml`, `awsQuery`, `ec2Query` | `codegen/src/codegen/{awsjson,restjson,restxml,awsquery}.gleam` |
| Runtime — credentials | `aws-config` crate (hand-written) | `src/aws/credentials.gleam` + `src/aws/internal/providers/*` (hand-written, M2) |
| Runtime — region | `aws-config` (hand-written) | `src/aws/region.gleam` (hand-written, M3) |
| Runtime — endpoints | `aws-smithy-types-endpoint` (hand-written rule-set evaluator) | `src/aws/endpoints.gleam` (hand-written, M3) |
| Runtime — retry | `aws-smithy-runtime::retries` (hand-written) | `src/aws/retry.gleam` (hand-written, M4) |
| Runtime — signing | `aws-sigv4` (hand-written) | `src/aws/internal/sigv4.gleam` (hand-written, M1) |
| Generated per-op shape | `OperationBuilder` + `serializer` + `deserializer` + typed `Input`/`Output`/`Error` | `build_<op>_request` + `parse_<op>_response` + typed `<Op>Input`/`<Op>Output` (no error sum yet) |

**Conclusion**: the architectural split matches — runtime is hand-written
and shared, codegen produces per-service typed wrappers that call into
the runtime. No drift here.

**Coverage**: 14.9% of cases pass on our generated code today. 0 fail
(every gap is an explicit "no dispatcher yet"). The Rust SDK passes
≈99% (a handful of `smithy-rs` ignored cases for explicit reasons).

**Honest delta**: we cover the entire "easy" empty-input-output slice.
The remaining 639 cases need typed I/O generation. Rust's emitter
produces those; ours does not yet. Hence the gap.

## 4. Documented skips — both projects

Cases neither project covers for systemic reasons (not bugs):

- `*HostWithPath*` (7 cases across protocols) — tests user-supplied
  custom endpoints with path prefixes. The behaviour belongs to the
  runtime's endpoint joining, not the per-op request builder. Skipped
  on our side because the test runner only asks the builder for a
  request; Rust handles via separate endpoint-resolution test.
- `*EndpointTrait*` (3 cases) — `@endpoint` hostPrefix substitution.
  Rust supports; we don't yet. Tracked.
- Smithy server-only (`appliesTo: "server"`, 41 cases) — never apply
  to client SDKs. Rust ignores too.

## 5. What's locked

These are the parts where any drift would be a regression:

- Runtime (M1–M4): 153 gleeunit tests + 763 endpoint cases. Same
  semantics as `aws-sdk-rust`'s runtime, byte-checked per the SigV4
  test suite and Smithy endpoint test cases.
- Smithy parser: 3 smoke tests against real DynamoDB + S3 models.
- Generator skeleton across 5 protocols: 120 protocol-test cases.

## 6. Next-iteration roadmap

Ordered by leverage (cases unlocked per unit effort):

1. **Typed primitive members for awsJson** — Int/String/Bool/Float
   structure fields. Unlocks SimpleScalarProperties-family cases
   across awsJson1_0 (3+ ops, ~6 cases) and awsJson1_1 (multiple ops,
   ~30+ cases).
2. **List + Map members for awsJson** — covers list/map cases.
3. **Typed primitive members for restJson1** — same primitive walker
   reused, plus `@httpLabel`/`@httpQuery`/`@httpHeader` binding
   handlers. Unlocks the biggest single corpus (272 cases).
4. **Per-operation error sum types** — Rust generates per-op
   `<Op>Error` enum from the `errors:` list. Needs the same in Gleam
   for typed error returns.
5. **restXml typed body** — XML serializer + deserializer.
6. **awsQuery/ec2Query typed body** — form-urlencoded with `.member.N.X`
   key flattening.
7. **`@endpoint` hostPrefix substitution** — clear the 3 doc-allowed
   skips.
8. **Pagination + waiters** (M7).
9. **Event streams** (M7 / post-v0.1).

## 7. Verification gating

A future agent picking up the work should keep these guardrails:

- After any emitter change, regenerate fixtures + service modules +
  dispatchers and re-run `gleam test`. Number of `fail` must stay at
  0. Number of `pass` must be ≥ the previous tally for every
  protocol. If a case regresses out of pass into anything else, the
  PR is blocked.
- After a `vendor/smithy` SHA bump, re-run
  `scripts/build-protocol-test-asts.sh` and inspect new cases — they
  land as `skip_no_dispatcher` automatically; growing skip count is
  acceptable, growing fail count is not.
- The per-protocol `skip_allow_list` entries in
  `test/protocol_tests_test.gleam` may only grow with an explicit
  written justification. The justification must reference either an
  upstream-Rust comparable behaviour OR a documented runtime concern.
